Шаблон. Заполненный пример — [отчёт о приёмке шаблона DoverAI](https://github.com/dover-ai/starter/blob/main/docs/AUDIT-2026-09-03.md).

## Вердикт

Одна строка, понятная нетехническому человеку: **готово к эксплуатации** / **готово с ограничениями** / **не готово**. Далее — два-три предложения о главном.

| | |
|---|---|
| Проверено утверждений | |
| Подтверждено находок | |
| **Гипотез отклонено проверкой** | |
| Осталось в реестре ограничений | |

> Строка про отклонённые гипотезы обязательна. Проверка, не отвергнувшая ни одного собственного предположения, — это согласие, а не проверка.

## Находки

По убыванию приоритета. Каждая — по одной схеме:

### N. Название находки одной строкой

**Приоритет:** высокий / средний / принято осознанно

**Суть.** Что не так, в двух-трёх предложениях, без жаргона.

**Доказательство.** Выполненный запрос и полученный ответ, замер, лог, вывод команды. Не «возможна утечка», а конкретное наблюдение, которое читатель может повторить.

**Причина.** Почему так получилось. Без этого исправление будет косметическим.

**Почему это важно.** Что именно теряет заказчик. Формулируется в терминах его бизнеса, а не механизма.

**Исправление.** Что сделать. Если сделано в ходе работы — что именно и где.

**Проверка исправления.** Повторное наблюдение после правки. Исправление без прогона исправлением не считается.

## Отклонённые гипотезы

Что предполагалось и не подтвердилось, с указанием, чем именно опровергнуто.

Раздел не признак плохой работы: он показывает объём проверки и защищает заказчика от находок, придуманных ради объёма отчёта.

## Подтверждено работающим

Таблица: что проверялось, как, результат.

Без этого раздела отчёт создаёт впечатление, будто не проверялось ничего, кроме найденного, — и обесценивает то, что в системе сделано правильно.

## Проверка защит намеренной поломкой

Таблица: что сломано — как отреагировало.

Отвечает на вопрос, срабатывают ли имеющиеся проверки вообще. Молчание в ответ на поломку — отдельная находка.

## Состояние после работ

Если проводились исправления: что изменилось в числах — тесты, покрытие, состав конвейера, число открытых ограничений.

## План доводки

Что осталось, с приоритетами и оценкой трудоёмкости. Для каждого пункта — условие, при котором его нужно закрывать.

## Границы проверки

Что **не** выполнялось: нагрузочное тестирование, испытание на проникновение, аудит инфраструктуры, проверка восстановления из копии — перечислить применимое.

Обязательная оговорка: отчёт показывает состояние на указанную дату по перечисленным направлениям и не является гарантией отсутствия уязвимостей.
