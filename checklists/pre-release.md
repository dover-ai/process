# Чек-лист приёмки

Заполняется перед передачей в эксплуатацию. Каждый пункт подтверждается доказательством — ссылкой на прогон, отчёт или воспроизводимую команду. Отметка «сделано» без доказательства отметкой не считается.

## Функциональность

- [ ] Поведение соответствует спецификации, согласованной на обследовании
- [ ] Расхождения со спецификацией зафиксированы письменно и приняты заказчиком
- [ ] Граничные случаи проверены: пустые данные, предельные объёмы, одновременные обращения
- [ ] Заказчик прошёл приёмочные сценарии на своих данных; сценарии внесены в протокол приёмки, который он подписывает вместе с актом
- [ ] Работа шла на очищенной копии; решение о данных соблюдено, список внешних сервисов в нём актуален

## Тесты

- [ ] Критичные сценарии покрыты автотестами
- [ ] Тесты проходят на чистом окружении, а не только на машине разработчика
- [ ] Установлен порог покрытия, сборка падает при его снижении
- [ ] Приёмочные тесты написаны отдельным исполнителем по спецификации, без доступа к коду (`tests/acceptance/`)
- [ ] Тесты запускаются у заказчика одной командой и в конвейере его репозитория
- [ ] Проверено, что тесты действительно ловят ошибки: сломай поведение намеренно — тест обязан упасть

Последний пункт важнее остальных. Тесты, которые проходят всегда, создают ложную уверенность и хуже, чем их отсутствие.

## Трассировка

- [ ] У каждого пункта спецификации есть тест или приёмочный сценарий (`docs/TRACEABILITY.md`)
- [ ] Пункты без теста перечислены, причина записана

## Безопасность

- [ ] Заполнен [чек-лист безопасности](security.md)
- [ ] Найденные проблемы либо исправлены, либо внесены в реестр ограничений с приоритетом
- [ ] Секретов нет ни в коде, ни в истории репозитория, ни в логах

## Поведение под нагрузкой

- [ ] Нефункциональные требования записаны с цифрой, базой и методом замера (ссылка на спецификацию)
- [ ] Полный паспорт: итоговый прогон выполнен, отчёт приложен (профиль, окружение и где сделан прогон, p50/p95, ошибки, что отказало первым, команда повтора)
- [ ] Базовый паспорт: в реестре ограничений записано «не нагружалось; первым откажет…»
- [ ] Проверено поведение на ожидаемых объёмах данных, а не на тестовых десяти записях
- [ ] Ошибки обрабатываются: отказ внешней зависимости не роняет систему целиком

## Интеграции

Заполняется, если в проекте есть интеграции.

- [ ] Таблица интеграций: система, есть ли песочница, что и когда проверено
- [ ] Контрактный тест на записанных ответах для каждой интеграции
- [ ] Отказ внешней системы (таймаут, ответ 5xx) не роняет систему — проверено
- [ ] Один сквозной прогон в песочнице выполнен, либо отсутствие песочницы записано в реестр ограничений

## Миграции и восстановление

- [ ] Если есть миграция: прогон на копии или синтетике объёмом из требований, сверка числа записей и контрольных значений, откат миграции — протокол приложен
- [ ] Полный паспорт: восстановление из резервной копии на чистый стенд выполнено, время замерено, контрольные записи на месте — протокол приложен

## Наблюдаемость

- [ ] Логи позволяют восстановить ход событий при разборе инцидента
- [ ] В логи не попадают пароли, токены и персональные данные
- [ ] Есть способ узнать, что система жива, без ручной проверки

## Развёртывание

- [ ] Сборка воспроизводима: та же версия исходников даёт тот же результат
- [ ] Процедура отката проверена, а не только описана
- [ ] Конвейер поставки зелёный на текущей версии
- [ ] Основная ветка защищена правилом «одно одобрение не от автора»; слияний в обход защиты в истории нет

## Передаваемость

- [ ] Проект развёрнут с нуля по инструкции исполнителем без доступа к рабочим заметкам, протокол приложен
- [ ] На передаче проект развёрнут повторно вместе с инженером заказчика. Если инженера нет — развёрнут на сервере или в аккаунте заказчика у него на глазах; в спецификации есть пункт «проект разворачивается с нуля по инструкции»; в протоколе записано, что проверка на передаче наша, а не внешняя
- [ ] Инструкция перечисляет требования к инфраструктуре; протокол фиксирует выполненные шаги и результаты без оценок; запись сеанса — только с согласия заказчика
- [ ] Документы сверены с кодом на дату сдачи; описание точек подключения собрано из кода
- [ ] Записаны архитектурные решения: через полгода логика не восстанавливается по коду
- [ ] Есть диаграммы уровня контекста и контейнеров (модель C4), текстом в репозитории; компонентные — там, где сложность оправдывает
- [ ] Диаграммы соответствуют текущему состоянию системы, а не первоначальному замыслу
- [ ] Реестр известных ограничений передан заказчику

## Итог

- [ ] Вердикт сформулирован явно: **готово к эксплуатации** / **готово с ограничениями** (перечислить) / **не готово** (перечислить блокеры)

Вердикт «готово с ограничениями» — нормальный результат. Умолчание об ограничениях — нет.
