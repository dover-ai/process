# Процесс разработки DoverAI

Как студия ведёт проекты: фазы работы, обязательные артефакты, роли и чек-листы приёмки.

Репозиторий открыт намеренно. Мы продаём проверяемость — значит, наш собственный процесс должен быть доступен для проверки, а не описан общими словами на странице услуг.

## Зачем это опубликовано

Заявление «ИИ ускоряет работу, инженер отвечает за результат» сегодня делает каждая студия, которая вообще упоминает ИИ. Проверить такое заявление нельзя никак — поэтому оно ничего не значит.

Здесь лежит то, что проверить можно: какие фазы проходит проект, какие артефакты обязаны появиться на выходе каждой из них, по каким критериям работа считается принятой.

## Стадия зрелости

Процесс складывается из практики, а не написан заранее под воображаемые проекты. На сегодня в нём зафиксировано то, что уже устоялось в работе; разделы будут дополняться после каждого проекта.

Мы намеренно не публикуем «полный фреймворк на все случаи»: набор правил, не проверенный на реальных задачах, обычно решает выдуманные проблемы. Новое правило появляется здесь после того, как одна и та же ситуация повторилась в третий раз.

Такой же принцип применяется к ролям: их пять, а не двадцать. Роль попадает в набор, только если у неё есть проверяемый результат работы.

## Как этим пользоваться

Материалы можно свободно брать и адаптировать под свою работу — лицензия MIT.

Учтите одно: набор ролей копируется за минуту, и сам по себе он мало что даёт. Работает не текст описания, а дисциплина проверки — привычка требовать доказательство там, где легко удовлетвориться правдоподобным ответом. Этому разделу посвящён [LESSONS.md](LESSONS.md), и он для нас важнее, чем описания ролей.
